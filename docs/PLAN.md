# 编写战斗计划 JSON

计划是一个 JSON 数组，每项描述一个动作。支持 `DEPLOY`（部署）、`RETREAT`（撤退）、`SKILL`（开技能）、`SKILL_END`（主动结束）和 `SWITCH_MODE`（模式切换）。时间单位为秒，战斗开始为 0；不支持注释、尾逗号或额外字段。

可以直接编写 JSON，也可以用 [图形化编辑器](EDITOR.md) 选择队伍、设置练度、点击地图并导出同一格式的计划。

## 最小部署

```json
[
  {
    "char_id": "char_替换为实际ID",
    "tile": [2, 3],
    "time": 10.0,
    "level": 1,
    "elite": 0,
    "facing": 0
  }
]
```

上面的 ID 和坐标只是模板，需按角色和地图修改。查询 ID：

```powershell
python tools/list_data.py --kind operators --query "干员名称"
python tools/list_data.py --kind map --stage "关卡ID"
```

## 坐标和朝向

`tile` 使用 `[行, 列]`，从 0 开始计数。第 0 行在地图最下方，第 0 列在最左侧；这与关卡原始数组的上下顺序不同。地图查询输出和 HTML 页面已经换成引擎坐标，可直接照着填写。

| facing | 朝向 |
| --- | --- |
| 0 | 右，列增大 |
| 1 | 下，行减小 |
| 2 | 左，列减小 |
| 3 | 上，行增大 |

只能部署在角色允许的地面或高台格，并且格子不能被占用。输入解析检查非负整数坐标；部署是否合法仍由地图和引擎判断。

## 完整字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `char_id` | 必填 | 干员 ID，例如本地角色表中的 `char_*` 键 |
| `tile` | 部署必填 | 部署 `[行,列]`；其他操作省略或填 `null` |
| `time` | 必填 | 最早执行时间；有限且非负 |
| `action` | `"DEPLOY"` | `DEPLOY`、`RETREAT`、`SKILL`、`SKILL_END`、`SWITCH_MODE`，大小写均可 |
| `mode` | `null` | 仅模式切换可指定：`0` 初始状态、`1` 技能状态；省略则切到另一状态 |
| `on_failure` | `"WAIT"` | 临时条件不满足时等待重试；`SKIP` 失败后跳过，`STOP` 失败后终止模拟 |
| `level` | `1` | 精英阶段内等级；须在该阶段 1 至等级上限之间，超出时报错 |
| `elite` | `null` | 精英阶段 0/1/2；省略时选择该角色数据中最高的已有阶段，建议明确填写 |
| `facing` | `0` | 朝向 0/1/2/3 |
| `skill_id` | `null` | 指定技能 ID；省略表示不挂载技能 |
| `skill_level` | `null` | 技能等级 1–10；8/9/10 对应专一/专二/专三，省略时取当前精英化和等级下已解锁的最高等级 |
| `auto_skill` | `false` | 部署项的手动技能是否满技力自动释放；自动触发与被动技能仍遵循自身流程 |
| `trust` | `0` | 信赖百分数 0–200，可有小数；属性收益在 100% 封顶 |
| `potential_rank` | `0` | 已增加的潜能数量，须在角色数据允许范围内；通常 0 对应一潜、5 对应六潜 |
| `module_id` | `null` | 模组 ID；不使用时省略或填 `null` |
| `module_level` | `0` | 模组等级；装备时必须指定该模组实际存在的正整数等级，未装备时为 0 |

选择技能后可以设置 `"skill_level": 7` 或 `"skill_level": 10`。实际范围和升级解锁条件取自本地表格，不能给未精英二的干员选择专精。指定 `skill_level` 必须同时指定 `skill_id`；技能和模组都必须属于该角色。省略技能等级表示选择已解锁的最高等级，不表示引擎会自动升级角色。回放在 roster 中保存每次部署采用的完整配置，逐帧单位通过 profile 关联该配置。

精英化、等级、信赖和潜能参与基础属性计算；已支持的天赋、特性和模组效果会按解锁条件及潜能选择参数。配置合法不代表该技能或天赋行为已完整实现，未覆盖能力通过机制诊断提示，见 [机制支持与缺口](MECHANICS.md)。

## 部署、开技能、撤退、再部署

```json
[
  {"char_id":"char_替换为实际ID","tile":[2,3],"time":10,"level":1,"elite":0,"facing":0,"skill_id":"替换为已解锁的手动技能ID","skill_level":1},
  {"char_id":"char_替换为实际ID","time":40,"action":"SKILL","on_failure":"SKIP"},
  {"char_id":"char_替换为实际ID","time":100,"action":"RETREAT"},
  {"char_id":"char_替换为实际ID","tile":[2,4],"time":180,"level":1,"elite":0,"facing":2}
]
```

撤退按 `char_id` 找当前在场单位。再部署仍需满足该角色的再部署时间、部署费用和席位限制；部署次数的费用变化由引擎处理。

`SKILL` 释放当前在场单位部署时配置的手动技能，不在操作项中临时更换技能。默认手动技能不会满技力自开；旧计划若依赖这一近似，可以在部署项显式设置 `"auto_skill": true`。自动触发和被动技能不能通过 `SKILL` 操作手动释放。

开技能会检查在场状态、技能类型、启动/持续状态、异常状态和技力，随后调用既有技能执行流程。机关交互尚未提供。

## 主动结束与模式切换

```json
[
  {"char_id":"char_替换为实际ID","time":60,"action":"SKILL_END","on_failure":"SKIP"},
  {"char_id":"char_另一名干员ID","time":80,"action":"SWITCH_MODE","mode":1},
  {"char_id":"char_另一名干员ID","time":100,"action":"SWITCH_MODE","mode":0}
]
```

这些操作作用于当前在场单位部署时配置的技能。只有技能说明明确声明“可主动关闭技能／可随时停止技能”才支持 `SKILL_END`；只有声明“可以在下列状态和初始状态间切换”才支持 `SWITCH_MODE`。无限持续、弹药技能或普通描述中的“切换”不会自动获得权限。无法识别声明时返回不支持，不强制修改状态。

主动结束不返还技力；清理当前技能的已实现临时攻防、范围与弹药状态，并调用已有结束事件。未开启时立即失败，启动中或状态禁止操作时按 `on_failure` 等待/跳过/停止。没有主动关闭声明的模式技能不能用 `SKILL_END` 免费切回。

模式切换采用两状态模型：技能状态保持生效，期间允许恢复技力；来回切换均检查并消耗技能表中的技力，复用已配置的启动动画。指定的模式已经生效时成功返回，不扣技力、不重复释放；启动过渡未完成时仍等待。`SKILL` 也能从初始状态开启模式技能，切回请使用 `SWITCH_MODE`。

说明文字直接支持操作权限；切换的技力、异常状态限制、动画及输入子阶段仍是候选模型，结果登记 `SKILL_CONTROL_TRANSITION_CANDIDATE:*`。本次没有补齐各角色特殊能力；缺少行为模板时另登记 `SKILL_CONTROL_EFFECTS_INCOMPLETE:*`。例如回血、阻挡数变化、多目标攻击、随机效果及结束爆发不能因操作成功就视为已完整实现。

计划按时间排序，同一时刻保持 JSON 数组中的顺序。动作在到达其最早时间的逻辑帧、普通实体更新之前尝试执行，不是预约必定成功的时间。若技力在随后实体更新中恢复到足够值，等待中的开技能操作会在下一帧重试；这一计划输入阶段不能直接当作原生玩家输入回调时序。

默认 `WAIT`：费用/席位/再部署冷却不足，或者技力不足、技能仍启动/持续、状态禁止开技能时等待，并阻塞后续整条计划。重复部署、位置不合法、单位不在场、没有技能或技能不能手动释放等永久失败直接跳过。`SKIP` 对临时失败也立即跳过；`STOP` 对任一失败立即结束模拟，结果原因为 `operation_failed`。

费用和席位等待可能挡住后面的撤退操作，技力等待也可能永远无法满足。需要按指定时刻尝试一次时使用 `SKIP`，需要失败立即暴露时使用 `STOP`。

## 操作反馈

结果中的 `operation_results` 保存全部计划项，`index` 对应原 JSON 中从 1 开始的编号。状态为 `succeeded`、`failed`、`waiting`、`unfinished`、`not_executed`；尚在运行而未到时间的项为 `pending`。同时保存计划时间、首次/最后尝试时间、实际执行时间、原因码、中文原因和上下文。

上下文包括所需/现有费用、席位、再部署冷却截止时间，或所需/现有技力、技能状态等。部署临时失败可在 `blockers` 中列出多项同时存在的限制。战斗结束时，仍等待的项标记未完成，尚未尝试的项说明是未到时间、被前项阻塞还是计划已终止。

回放页原事件流的“操作/波次”筛选显示等待、失败和成功。等待只在状态或原因变化时增加事件，连续等待不会每帧刷一条记录。撤退显示为撤退事件，不再当作干员倒下。

操作成功表示该操作已进入现有执行流程，不表示技能能力已完整覆盖；仍应查看机制和行为警告。若技能执行器因缺少参数等原因未完成，反馈为 `skill_rejected`，并记录执行后的技力和释放次数；这类未支持流程可能已经消费技力，不模拟为原生无副作用拒绝。

公共运行入口和直接创建 Battle 都会检查角色属性范围、技能归属与解锁、技能等级及专精解锁、模组归属与等级、表中声明的精英化/等级/信赖条件。模组检查需要 `uniequip_table.json` 和对应的 `battle_equip_table.json`，非零信赖门槛还需要 `favor_table.json`。错误会标明计划项编号，不再把越界等级截断或选取邻近模组等级。

这些检查不包含账号持有情况、材料消耗、模组任务完成情况，也不替代地图部署判定。撤退和开技能项只需角色 ID、时间、动作，不要求提供部署配装；属性、技能和模组配置只在部署项生效。

## 当前无法表达

- 主动结束持续技能、切换特殊技能模式、操作机关或触发分支。
- 在战斗途中改变精英化、等级、技能等级或装备，或者模拟技能升级过程。
- 等待“某敌人出现 / 某单位死亡”后执行的条件动作。
- 在页面中修改计划并立即重新计算。

空数组 `[]` 是合法计划，表示不进行干员部署。编辑完计划后需重新运行模拟，页面读取的新 JSON 才会反映改动。
