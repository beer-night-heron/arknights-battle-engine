# 编写战斗计划 JSON

计划是一个 JSON 数组，每项描述一个动作。当前支持 `DEPLOY`（部署）和 `RETREAT`（撤退）。时间单位为秒，战斗开始为 0；不支持注释、尾逗号或额外字段。

## 最小部署

```json
[
  {
    "char_id": "char_替换为实际ID",
    "tile": [2, 3],
    "time": 10.0,
    "level": 1,
    "elite": 0,
    "facing": 0
  }
]
```

上面的 ID 和坐标只是模板，需按角色和地图修改。查询 ID：

```powershell
python tools/list_data.py --kind operators --query "干员名称"
python tools/list_data.py --kind map --stage "关卡ID"
```

## 坐标和朝向

`tile` 使用 `[行, 列]`，从 0 开始计数。第 0 行在地图最下方，第 0 列在最左侧；这与关卡原始数组的上下顺序不同。地图查询输出和 HTML 页面已经换成引擎坐标，可直接照着填写。

| facing | 朝向 |
| --- | --- |
| 0 | 右，列增大 |
| 1 | 下，行减小 |
| 2 | 左，列减小 |
| 3 | 上，行增大 |

只能部署在角色允许的地面或高台格，并且格子不能被占用。输入解析检查非负整数坐标；部署是否合法仍由地图和引擎判断。

## 完整字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `char_id` | 必填 | 干员 ID，例如本地角色表中的 `char_*` 键 |
| `tile` | 必填 | 部署 `[行,列]`；撤退填 `null` |
| `time` | 必填 | 最早执行时间；有限且非负 |
| `action` | `"DEPLOY"` | `DEPLOY` 或 `RETREAT`，大小写均可 |
| `level` | `1` | 精英阶段内等级；属性计算按该阶段等级上限截断 |
| `elite` | `null` | 精英阶段 0/1/2；省略时选择数据中最大等级上限的阶段，建议明确填写 |
| `facing` | `0` | 朝向 0/1/2/3 |
| `skill_id` | `null` | 指定技能 ID；省略表示不挂载技能 |
| `trust` | `0` | 信赖百分数，通常 0–200；属性收益在 100% 封顶 |
| `potential_rank` | `0` | 已增加的潜能数量，通常 0–5；0 对应一潜，5 对应六潜 |
| `module_id` | `null` | 模组 ID；不使用时省略或填 `null` |
| `module_level` | `0` | 模组等级；使用模组时一般为 1–3 |

没有 `skill_level` 字段。当前技能取数据 `levels` 数组的最后一级；无法通过计划选择其他技能等级。挂载某技能并不意味着该技能所有行为均已实现，见 [机制支持与缺口](MECHANICS.md)。

## 部署、撤退、再部署

```json
[
  {"char_id":"char_替换为实际ID","tile":[2,3],"time":10,"level":1,"elite":0,"facing":0},
  {"char_id":"char_替换为实际ID","tile":null,"time":100,"action":"RETREAT"},
  {"char_id":"char_替换为实际ID","tile":[2,4],"time":180,"level":1,"elite":0,"facing":2}
]
```

撤退按 `char_id` 找当前在场单位。再部署仍需满足该角色的再部署时间、部署费用和席位限制；部署次数的费用变化由引擎处理。

计划按时间排序，同一时刻保持 JSON 数组中的顺序。动作在到达其最早时间的逻辑帧执行，不是预约必定成功的时间：费用不足、席位已满、再部署时间未到会等待，并阻塞后续计划；重复部署在场角色、占用或不可部署格等情况会跳过；撤退不存在的角色也会跳过。

公共运行入口会拒绝未知字段、不支持的动作、无效基础类型，以及本地表中不存在的角色/技能/模组 ID。它不会检查全部角色与技能的搭配、模组装备条件、等级上限或地图有效性；请根据当前数据配置，不要依靠输入检查替代这些条件。

## 当前无法表达

- 在某个时刻手动开技能或关闭自动释放。
- 指定技能等级、专精等级或单独的技能升级过程。
- 等待“某敌人出现 / 某单位死亡”后执行的条件动作。
- 在页面中修改计划并立即重新计算。

空数组 `[]` 是合法计划，表示不进行干员部署。编辑完计划后需重新运行模拟，页面读取的新 JSON 才会反映改动。
