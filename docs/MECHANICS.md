# 机制支持与未完成内容

本页描述当前主战斗引擎的实现范围。已有计算流程与“全部角色、全部关卡都能精确模拟”之间仍有差距；数据覆盖、技能行为和时序假设都可能限制结果。

## 已接关卡适配与证据边界

维护版 0.45.125 合入三个明确启用范围的适配。VEC 第三期目标为 `act3break_08`，接战备补给、污染、净化／消杀机关、Touch 两阶段、召唤追踪、吸收和按异常类型适应免疫；污染直接选择排除迷彩／召唤物，全场吸收仍可影响它们。适应四层后实际免疫，通知刷新寿命，到期重新适应；本图共享免疫天赋禁用，不额外启用。过灌注向 Touch 移动，Touch 继续自身路线，一阶段移速下限不扩大到二阶段。

Mansfield 适配限 `act15d0_ex08`，接囚犯攻击计数／解放／重新禁锢、在场敌人的一次全场解放、预置可受击装置及领袖重生／技能；远程攻击走真实弹体，缓存发射时参数。反装甲步兵适配限 `act18d0_ex03` 及其突袭变体，榴弹发射一次后延迟切近战；已飞榴弹保留原倍率，切换不清除已有控制。源数据等级与有效覆盖共用读取，专属动作资源仅在目标关卡加载。

这些适配不表示任意关卡环境、敌方技能或原生逐帧行为全部完成。吸收播放／通知、异常监听、连续终点导航、冲刺接触、囚犯光环与技能交接、榴弹模式切换／碰撞仍登记候选。定向检查和同种子重建只验证模拟实现，不能替代实战核对；不会修改概率、敌人数值或路线来追求某方案通关。

交接中尚未修复的续编秒数显示／最小值舍入、按舍入秒数定位前移采样帧、死亡摘要与窄侧栏布局问题继续保留记录；偶见维什戴尔弹道回退诊断不能单凭标签判定真实缺弹体。多预置装置分别操作的完整编辑器入口、维什戴尔 S2／S3 本体攻击等仍未完成。

维护版 0.45.126 进一步接入 CW 普通地图 `act25side_ex03` 的重力／按钮、碎石计数／轨道碰撞与敌方附加效果，以及 Dublin 普通地图 `main_09-10` 的折射／沉默、倒柱／障碍导航、悬浮落地、石像鬼形态与感染。碎石直接目标选择使用源单位的自身位置及碎石的当前格；范围伤害独立处理。敌方普通攻击类型在出手和命中共用，避免术师法伤被物伤回退覆盖。这些地图中的准确光环通知、碰撞形状、状态／动画交接和特殊导航仍有限制。可选石像鬼倒地／重生动画保护默认零窗口，不把实验搜索的帧数当作通用规则。

31 人／36 技能的静态校对发现了 14 类有公开规则依据的实现错误，维护版 0.45.127 已修正对应规则，见 [技能支持中的修正记录](OPERATOR_SKILLS.md)。新检查覆盖这些错误及相关生命周期／伤判反例，不代表所有机制、组合和原生逐帧相位完全一致。

## 0.45.128 补充的公开规则与边界

斩业星熊的常规血条与负生命债务现在分开；伤害增加债务，允许的治疗／属性回复先还债，负债满额才触发死亡。最大生命改变只改变债务上限，不按比例缩放已欠数。已接普通路径；特殊不死／免死回调、所有强制重设节点及额外生命池仍未完整绑定，不能称三池与当前原生通知完全一致。[生命值](https://prts.wiki/w/生命值)

来源盲区用于直接攻击／医疗及新约借范围轰炸的选择，保留范围数据和不依赖直接选择的斩杀光环。目标格上的遮挡物忽略，现存遮挡对象的生死／位置动态查询；未自动实例化的预置装置只保初始阻挡并明确诊断生命周期缺口。中心连线是候选，PRTS 对中心周边采样本身标为存疑；没有据基本规则宣称全部遮挡几何完成。[视野范围](https://prts.wiki/w/视野范围)

DEFAULT 属性自动优先级接三类属性修饰器总和乘 1000，最终倍率不参与；指定黑板键时改为绝对值总和。初始数值按 float32 转 Q32.32，在累加与乘 1000 后作最近偶数舍入；相等优先级保留先创建者。有限失效项继续消耗寿命，只暂停触发钟；复杂周期刷新和动态优先级仍拒绝。[BUFF](https://prts.wiki/w/BUFF)

| 特殊对象更新顺序 | 普通干员和敌人已按优先级/创建序处理；特殊机关、召唤等不能默认沿用同一完整规则 |
| 属性和技力精度 | 部分路径有离散计时或高精度处理；未统一覆盖所有角色及恢复速度 |
| 输入与操作反馈 | 已记录当前支持操作的成功、等待、失败、未执行及具体原因；账号持有、材料/任务条件和特殊机关/能力施加的操作限制仍需各自机制实现 |
| 页面编辑计划 | 图形编辑器支持关卡/队伍练度、点格部署、时间操作、导入导出与本地运行；地图为计划示意，运行时费用/冷却等仍由引擎决定。同一干员在方案内统一配装 |
| 数据版本记录 | 回放保存引擎版本与运行选项；未自动归档全部输入数据和版本 |

## 时序模式

- `fast`：使用标称出怪时间，是命令行默认值。
- `client`：加入逐帧出怪工作项与交接规则，再由战斗中的离场状态放行后续分段/波次；不能保证所有特殊动作都精确。
- `frame_core`：按动作队列生成分段内出怪帧，实时清场门控制后续分段/波次。特殊分支与条件动作仍有限制，不能当作所有关卡的最终时序。

显式路线预览在 `client` 与 `frame_core` 中共用两次游标、0.3 秒间隔，结束时刻参与分段交接；这仍是预览执行时序候选，不代表所有动作协程及同帧顺序均已验证。

波次门以清场、排程完成及最后生成后的交接为下界，等待会整体平移后续队列，不用预填离场帧。不同波次保留各自实际开始时间。`maxTimeWaitingForNextWave` 超时在当前分段队列完成后处理，不取消已进入分段的生成项；尚未进入的分段可以跳过，已生成的敌人继续存在。此超时/交接模型仍标为候选，需要特殊场景的现场验证。
- `enemy-attack-timing=float`：默认敌人动画与冷却衔接路径。普通攻击先等待动画结束，结束时余量小于半帧可当帧续攻；大于等于半帧则余量向上取整并在归零下一帧可起手。目标、状态与待命中检查继续生效。
- 半帧分支规则依据用户确认；动态动画速度、打断及特殊能力交接尚未完整覆盖。`SimulationAssumptions.enemy_attack_animation_rearm=false` 可恢复原严格倒数模型；0.42.4–0.42.5的单位零值容差配置不再参与计算。
- 普通近战攻击间隔短于原动画时，启动阶段按比例缩短前摇与动画；`SimulationAssumptions.melee_attack_animation_interval_scale` 可关闭此候选。动态攻速、特殊动作及远程动画不在该规则内。
- `enemy-attack-timing=mortar_frames`：特定炮兵的可选整数帧间隔模式；不是所有敌人统一整数化的开关。

这些选项用于表达不同模型，不表示选择某个模式就关闭了其他机制缺口。默认参数中仍有校准规则，例如受击半径、避障形状、传送等待边界和部分首轮攻击间隔；详见 `SimulationAssumptions`。

可见出生等待后若紧接当前位置的 MOVE，默认结束帧消费该原地节点、下一帧才继续向后续节点运动；`initial_wait_zero_move_handoff=false` 可恢复旧同帧继续移动模型。等待后直接通往其他位置的 MOVE 保持原路径。已接入的角色形态从零阻挡恢复为正阻挡时，默认下一帧恢复扫描；`form_block_resume_next_frame=false` 可恢复旧同帧扫描。这两项是实战局部支持的候选，内部等待余量、形态通知与其他路线尚未完全验证，不改变途中等待、隐藏等待或普通伤害时序。

## 如何判断一局结果是否可用

先检查 `behavior_warnings` 与 `mechanic_warnings`，再看 `unsupported_behavior_nodes`、`unsupported_mechanics` 的具体项，以及本次 `assumptions`。严格行为模式只会阻止未支持的行为节点，不能证明全部机制、几何或时序正确。

零警告说明这局没有触发已经登记的缺口；尚未识别的遗漏和近似仍可能存在。尤其是新角色、复杂技能、特殊机关、波次清场门槛与精确弹道，需结合上述支持范围评估，不能只依据最终胜负。
