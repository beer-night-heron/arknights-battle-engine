# 机制支持与未完成内容

本页描述当前主战斗引擎的实现范围。已有计算流程与“全部角色、全部关卡都能精确模拟”之间仍有差距；数据覆盖、技能行为和时序假设都可能限制结果。

## 已有流程

| 部分 | 已实现内容 | 适用边界 |
| --- | --- | --- |
| 战斗与计划 | 部署、撤退、再部署、费用、席位、胜负与超时 | 不支持条件计划和手动技能动作 |
| 属性与伤害 | 等级、精英、信赖、潜能、部分模组，物理/法术/真实伤害与属性修正 | 特殊天赋、模组效果取决于具体实现 |
| 移动与路径 | 连续坐标移动、地图导航、等待、传送、部分避障与位移效果 | 碰撞、挂点、特殊路线边界仍有近似 |
| 阻挡与索敌 | 周期扫描、目标缓存、目标排序、攻击链与间隔衔接 | 特殊优先级与实体形状不能一概视为完全支持 |
| 攻击 | 起手、前摇、延迟命中、攻击间隔、部分攻速变化处理 | 缺少单位时序数据时采用回退值 |
| 弹体 | 已配置弹体的发射、飞行、到达与伤害；可选三维敌方发射挂点、目标HIT、二维/三维距离与到达容差 | 配置覆盖、转身曲线、动态受击骨骼和同帧推进边界待完善 |
| 技能与技力 | 部分恢复类型、启动、生效、结束、技力锁、持续/充能等流程 | 手动技能自动释放；技能等级固定取数据最后一级 |
| Buff 与状态 | 属性修正、叠加、控制、部分元素效果和行为模板解释 | 未覆盖节点/事件或能力会限制整段行为 |
| 特定能力 | 怒潮凛冬 S2 的锤击、溅射、高台回响及相关模组；部分敌方全场加成 | 这些规则不自动推广到其他技能和角色 |
| 重复运行 | 固定随机种子、抽取计数、并行批量与确定性复用 | 正确复现要求输入数据、计划、模式和引擎版本一致 |

## 仍需完善

| 缺口 | 当前状态 / 影响 |
| --- | --- |
| 手动技能控制 | 尚不能在计划中指定释放时刻、禁止自动释放或表达按条件开技能 |
| 技能等级选择 | 尚无计划字段；当前使用技能数据最后一级 |
| 全角色、天赋与模组覆盖 | 行为解释器逐步覆盖；仅有表格条目不能保证机制完整 |
| 完整关卡事件 | 部分特殊动作、动态波次条件、预定义单位和机关尚未完整接入 |
| 弹体端点与更新顺序 | 配置支持三维挂点、目标HIT、运动维度和到达容差；当前新弹体从后续逻辑帧推进，特殊出生流程、完整目标骨骼与帧内阶段仍有缺口 |
| 动画事件出弹 | 显式等待动画事件的普通远程攻击采用量化float32跨阈值计时候选；动画初始时间、速度变化和事件交接阶段仍待完善，不统一给伤害加一帧 |
| 远程攻击结束与移动衔接 | 普通远程攻击按动画时长转换为整数帧，随后跨两帧再恢复自主位移；该候选模型未完整覆盖特殊动作、打断与不同攻速。缺失动画时长时保留回退流程 |
| 远程出生索敌相位 | 候选模型按出生后第3、6等帧进行初始空闲扫描，不追加第2帧单次查询；攻击间隔结束仍立即搜索并从该帧重新建立周期。部分敌人首轮起手、原生调用阶段与特殊出生动作仍待完善 |
| 传送门时序 | 已有入口/隐藏/出口流程，但不同动作衔接与首动时刻仍待完善 |
| 目标范围与碰撞 | 实体受击半径等存在可替换默认参数；特殊几何与同帧位置来源仍有限制 |
| 特殊对象更新顺序 | 普通干员和敌人已按优先级/创建序处理；特殊机关、召唤等不能默认沿用同一完整规则 |
| 属性和技力精度 | 部分路径有离散计时或高精度处理；未统一覆盖所有角色及恢复速度 |
| 输入与操作反馈 | 基础字段和 ID 校验已有；角色装备条件、全部部署失败原因和跳过动作尚无完整独立报告 |
| 页面编辑计划 | 页面只读取已有模拟数据；修改计划后需重新运行 |
| 数据版本记录 | 回放保存引擎版本与运行选项；未自动归档全部输入数据和版本 |

## 时序模式

- `fast`：使用标称出怪时间，是命令行默认值。
- `client`：加入逐帧出怪工作项与交接规则；已有适用场景，但不能保证所有特殊动作都精确。
- `frame_core`：按静态动作队列生成出怪帧。需要依赖战斗状态的波次清场门槛等仍有限制，不能当作所有关卡的最终时序。
- `enemy-attack-timing=float`：默认敌人浮点间隔路径。
- `enemy-attack-timing=mortar_frames`：特定炮兵的可选整数帧间隔模式；不是所有敌人统一整数化的开关。

这些选项用于表达不同模型，不表示选择某个模式就关闭了其他机制缺口。默认参数中仍有校准规则，例如受击半径、避障形状、传送等待边界和部分首轮攻击间隔；详见 `SimulationAssumptions`。

## 如何判断一局结果是否可用

先检查 `behavior_warnings` 与 `mechanic_warnings`，再看 `unsupported_behavior_nodes`、`unsupported_mechanics` 的具体项，以及本次 `assumptions`。严格行为模式只会阻止未支持的行为节点，不能证明全部机制、几何或时序正确。

零警告说明这局没有触发已经登记的缺口；尚未识别的遗漏和近似仍可能存在。尤其是新角色、复杂技能、特殊机关、波次清场门槛与精确弹道，需结合上述支持范围评估，不能只依据最终胜负。
