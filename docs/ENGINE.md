# 主战斗引擎的组成

主入口是 `arksim.battle.Battle`。单局在默认 `1/30` 秒的逻辑步长内推进，`run()` 一直执行到生命归零、所有已排程敌人处理完毕，或默认 600 秒上限。`step()` 可供程序逐帧读取状态。改变回放采样密度不会改变逻辑步长。

## 模块职责

0.45.135 接通 DEFAULT 显式／黑板优先级创建和开始事件到后续事件的黑板预检，精确捕获子项创建时的参数。只读属性投影支持已核叶项的胜出、失效与精确派生清理；复杂回调、合并策略和非法输入仍前置拒绝。常规 `NoSourceDamage` 使用现有目标伤害流程，无干员输出／击杀归属。敌方黑蚀读取数据库敌方子树，按模板周期恢复攻击力和结算伤害，结束或死亡时清理家族，不叠加旧连续最终伤害近似；主时钟仍由元素控制器承接，原生完整通知相位未闭合。音效／特效字段保留，普通瞬时视觉节点明确标记未渲染。

0.45.134 从初始黑板建立原生周期钟：`interval`、`first_trigger_interval` 与 `trig_cnt` 覆盖定义中的周期、首次间隔和次数，后续改黑板不重建计时器。显式即时触发类型不启用周期；有限／无限有效触发类型可由黑板补齐定义中的 -1 周期，缺值或非法值在出生前拒绝。注册 Buff 按精确周期计时器的已核调用路径，每次更新至多触发一次，保留超时余量，在回调前加回周期；旧未注册适配保留原赶帧约定。整体出生帧、寿命截止限制与提交相位不因此全部改写为原生时序。

0.45.133 接有限失效项的寿命钟：失效暂停触发但不停寿命，恢复保原触发余量和次数，明确 `set_frozen` 仍暂停两个时钟。有限独立项支持沉默／晕眩响应，有限 DEFAULT 支持按优先级恢复，响应与覆写混合继续拒绝。默认持续时间键是 `duration`，显式键优先，未找到数值时回退定义；仅影响真实有限项。

0.45.132 的 `buff_database.py` 只解析数据库引用，效果仍由现有 Buff 容器、行为解释器和实体接口执行。定义来自数据根目录的 `buff_table.json`；按检索键克隆实际定义及其运行键，只合并引用黑板，普通字段不覆盖数据库。解析在相关事件／组件预检之前完成，原表和调用方模板保持不变。只展开已接创建节点，旧命中附件适配维持原引用；读到定义不表示所有标志、覆写和附属模板均已支持。

0.45.131 从同一数据修订的 `ep_breakbuff_table.json` 读取精确键和敌我持续时间，自动标记经过注册／组件或既有敌方配置创建的 Buff。元素爆发子项不因同名前缀继承标记。技能进度节点先核实真实 `SkillProgressHooker` 资源；目前只映射有限时间缓存和解锁，Buff 时钟独立推进。0.45.130 的“技能所属 Buff 集合应一并冻结／等待自动发现”解释已撤回；此节点并不要求这个集合。完整 Hooker 恢复模板、共享黑板与其他进度类型仍待接入。`FinishDerivedBuff` 的已核默认分支复用现有精确派生清理与提交队列，父项继续存活；未知覆写表分支仍拒绝；简单叶的清理后属性投影已接，复杂回调保留拒绝。数据库定义缺失的整段模板仍拒绝。

0.45.130 将浮空／缚地的申请、计数抵消、开始时重量倍率和状态入口接到现有 Buff 容器；敌方元素爆发冷却读取恢复速度，独立周期子项按自身钟运行。`set_frozen` 只暂停时钟，不撤属性／状态；技能进度锁与凯尔希迁移共用剩余时间接口，结束及退场解除来源锁。`FinishAllBuffsWithCertainAbnormalFlag` 标记真实实例并沿原阶段结束派生，不强制重排整局更新顺序。通用元素爆发自动标记、我方附属爆发钟、技能所属 Buff 自动发现、控制退出／导航和未出生清理相位仍有明确限制，未知组合保持诊断或拒绝。

0.45.129 扩展 `health.py` 的可选额外生命与不死约束，以及 `buffs.py` 的抵抗／迟钝双钟、永久独立项沉默／晕眩响应。`disableOverride` 按资源原值保留，独立项在预检、登记与提交阶段均不复用旧实例，重复组件绑定仍拒绝。`behavior.py` 的负生命设置／条件、单异常／免疫条件由敌我共用实体接口执行；全事件先检查实体类型、数值和变体。生命周期相位和未绑定的复杂能力继续显式登记，不把字段枚举当成整棵模板执行闭合。

0.45.125 将本地授权副本的最终修正按差异移植回主引擎，保留已有通用模板、Buff 覆写、四类属性池与顺序预检。`vecbreak.py`、`mansfield.py`、`wdex.py` 分别接入明确关卡标记下的补给／污染、囚犯和反装甲步兵，不是新内核，也不自动推广为所有敌人或环境系统支持。

0.45.126 继续合入 `cw.py` 与 `dublin.py` 的限定地图适配，接出生、目标、伤害、移动、阻挡、死亡和状态导出。敌方普通攻击的类型共用查询；不覆盖已有模板执行和属性计算。石像鬼动画保护由输入中的可选 `dublinUserAssumptions` 配置，默认窗口为零；动画长度有静态依据，精确免伤／选择与交接仍是实验候选。

0.45.127 修正校对发现的 14 类规则偏差。偷取按来源保存并接最终加算；格挡通知、格挡取消反制及反隐／迷彩资格共用入口。初始通行格另存只读资格，不随动态导航障碍变化；敌方路线跳变有独立标记，避免雪地把传送当步行离开。形态清理沿现有 Buff 生命周期结束家族，在既有阶段恢复原已挂载的自身组件，不从形态名称推定未绑定的原生模式索引。

0.45.128 增加主引擎使用的 `health.py` 和 `vision.py`，前者分离普通血条与负生命债务、统一伤害／治疗／属性回复的生命重设，后者只处理来源盲区资格，不把攻击范围缩小。负生命的特殊事件与额外生命池、视野装置的完整自动出生／摧毁生命周期及中心周边采样仍有边界。Buff 属性自动优先级接已知公式的整数结果，复用现有容器与预检；复杂舍入／刷新并未因此自动开放。

模式基础攻击加成使用独立字段，先作用于基础攻击，再经过普通技能／编队／祝福和注册四池；可露希尔既有携带加成不重复登记。敌方发射上下文保留当次伤害类型、技能附件、破甲及模式倍率，飞行后不改读新的攻击模式，眩晕在命中时附加。片段等待读取实时开始时间，不向等待项占位坐标导航；动作队列尊重已经选择的隐藏组。

关卡适配共用数据层的等级继承与有效字段合并，忽略 `m_defined=false` 占位值，并以副本加载技能覆盖，避免污染共享敌人表。`stage_attack_timing.json` 的动作资源只合入对应关卡的时序表。职业掩码中 TOKEN 为 128、TRAP 为 256；污染的直接选择与全场范围 Buff 的目标规则分开。技能准备不在对应适配中重复登记实际能力启动，原生完整通知相位仍候选。

魂灵之影仍由已有运行器接入：出手时优先未带残影目标，在该组内随机选择；组为空时在全体可选地面目标内随机。只读候选查询不耗随机数，使用现有 `wisdel_ward_target` 命名记录；返还自身技力沿原技能结束模板。该选择规则依据用户实测，原生抽签相位与跨机制随机流未完全闭合。

0.45.124 的 `behavior_preview.py` 是注册事件预检的只读属性投影，共用原 Buff 定义和属性 getter，不是另一套战斗内核。只有实体变更后还要读取属性／外部黑板的事件才启用，保留无需此类读取的旧分支语义。未知分支若得到不同属性状态，在副作用之前拒绝；已知分支各自持有快照，最多保留既有 32 个抽象状态。

组件中的普通创建会请求提交，普通注册 Buff 回调的同名创建只入队，范围创建另行请求提交；同容器提交重入继续延迟，跨容器可即时提交。预览按这些现有入口保留可见性，不交换全局更新顺序。原始 `FinishBuffsById` 默认字段可用于按键结束；前序黑板决定键时使用当前抽象值，精确父家族排除待结束子项。来源筛选、宿主、减层、排除本项及延迟覆写变体仍拒绝，不猜一般来源规则。准确原生事件／缓存与通知相位继续标候选。

0.45.123 在主引擎 `BuffContainer` 内继续接入覆写事件与四类属性池。攻击、防御、最大生命及敌方移速使用共用计算函数：先直接加值，再乘相加的直接倍率，再加最终加值，最后乘各项最终倍率；负最终倍率按值加一补正，直接倍率下限为零。取源实体属性、其余属性公式及精确固定点运算仍未开放。公式见 [PRTS：数据基础](https://prts.wiki/w/数据基础#属性基本公式)。

注册 `MAX_HP` 与既有编队、形态、技能及光环倍率合并，号角既有最终生命倍率在最终加值之后计算；提交后保持常规生命比例，最大生命下限为 1。敌方保存注册效果之外的基础生命，既有生命调整修改该基础，效果到期后保留这部分调整。属性回复读取更新后的最大生命，反复提交不会额外回血；旧未注册属性保持原适配边界。常规比例和下限见 [PRTS：生命值](https://prts.wiki/w/生命值) 与 [数值范围](https://prts.wiki/w/游戏数值范围)。

最大生命变化不缩放已有负生命欠款；斩业星熊的旧有符号生命存储在读取常规比例时映射为常规一血。此处修正比例及欠款保留，不表示已将常规、溢出、负生命完整拆成原生三池。债务上限下降后的即时死亡通知和完整特殊生命交接仍需核实；不会据未知通知规则直接击杀或补血。

覆写基本规则见 [PRTS：BUFF](https://prts.wiki/w/BUFF)。五种已接策略可执行已核生命周期事件树；`UNIQUE` 保留最早项及原周期、黑板和剩余触发预算，新项经开始通知后禁用并结束。`EXTEND` 取旧剩余与新持续时间的较大值，新持续时间为零时将旧剩余置零；`EXTEND_TIME` 累加新持续时间。刷新／加时合并的周期、预算和快照仍未开放。按明确覆写名分组，混用旧适配／不同策略明确拒绝。

受限 `STACK` 只合并持续时间、属性、状态、模板／事件树、层数上限及清层方式一致的原型。属性修饰器原值先按层数缩放，再参与四类属性池；保留最早实例与参数，新项的开始／禁用／结束动作各执行一次。有限效果按原周期逐层衰减，也支持到期清空；无限效果无自动衰减。到顶刷新、有效层数限制、周期合并和不同原型仍未接入。

`DEFAULT` 支持有限和永久项，优先级相同保留先创建者；失效项暂停触发钟，有限寿命仍流逝，胜出项退出后恢复下一未结束项及其原触发余量／预算。状态按实例撤销／恢复，自身启用／禁用事件不受失效过滤。初始 `priorityBBKeys` 按值的绝对值之和乘一千计算；未指定键的属性自动优先级累加 ADDITION／MULTIPLIER／FINAL_ADDITION，排除 FINAL_SCALER。输入按 float32 转 Q32.32，累加后乘一千并作最近偶数舍入，支持小数与有符号属性优先级；缺键绑定、非法值和溢出拒绝，动态重算未接。未迁移的负优先级旧适配沿原模型。

普通创建／注册读取并保留 `isDamageMissable`，不因此自行抽随机数或阻止创建。其已核含义是：弹道攻击未命中时跳过启用该标记的附件。通用创建与弹道附件不能混成同一判定；旧命中附件适配还未统一此接口，未支持的显式失误变体继续拒绝。[命中率](https://prts.wiki/w/命中率)

动作内及范围创建可使用明确 `disableOverride=true` 的已核新策略，独立拥有寿命、周期和黑板，并可绑定精确父实例；独立 DEFAULT 项也可有有限寿命。0.45.134 进一步允许不合并实例的 DEFAULT 按原实例绑定父项，包含失效项；父项退出只结束自己的本地／跨容器家族，并沿同组选择恢复其他家族项。此规则可用于已有支持的属性创建／范围入口；显式与黑板优先级的 DEFAULT 属性叶创建已接，只读预检保留复杂回调与非叶交接限制，不能将直接登记支持等同于所有树均开放。合并策略的父项归属仍拒绝，也不据此推定一般来源隔离规则。

实际属性池、策略兼容和优先级在登记及组件出生前复用同一预检，防止绑定后新增冲突或基础属性改变而产生部分效果。状态切换、最大生命与清理沿原提交边界，准确原生通知／缓存、事件内变化的赶帧余量及固定点精度仍为候选。这些是五种策略的受限入口，不表示全部 Buff 或复杂技能已自动执行。

同优先级顺序、有限失效寿命和初始优先级舍入已有依据并已接入。一般来源独立、合并触发次数／计时刷新、扩时快照和复合参数节点算术顺序仍需继续定位／解析；未找到完整说明不等于全站没有，已知而未编码的能力也不归为必须采集。

0.45.121 将恢复属性、黑板条件／默认值、实体属性快照和黑板有限触发预算集中接入现有流程。注册 `HP_RECOVERY_PER_SEC` 与 `HP_RECOVERY_PER_SEC_BY_MAX_HP_RATIO` 的加值和旧恢复速率合并，在受益者原计时器逐点回复；当前最大生命参与比例速率，满血不积存治疗，同帧不重复计时。原禁疗包与属性回复保持区别，既有运送模式压零两种生命回复的流程保留。注册 `SP_RECOVERY_PER_SEC` 加入自然回复速率，不替代攻击／受击回复，不绕过技能作用、起手、技力阻塞或上限；特定整点候选计时仅在没有新增速率时沿原分支。三种属性只开放加值及已有我方恢复控制器，敌方接收者和未知倍率在范围为空时也先拒绝。

`EnsureBlackboardDefaultValue` 在副本核完整批次，按显式覆盖开关补数字／字符串默认值。`FilterByExecuteBlackboardValue`、`IsBlackboardEqualWithFloat` 和不读取外部 Buff 的 `IsBlackboardEqualWithString` 共用标量条件，缺键为失败，未知条件／坏类型明确拒绝；顺序状态预检知道这些分支结果。数值比较仍采用当前模型的比较精度，没有据此证明当前原生全部浮点／定点边界。

`AssignAttributeToBB` 可快照当前模型的最大生命、攻击、防御、法抗与敌方移动速度；`AssignHpRatioToBB` 只读常规血条比例，负生命／溢出部分不进入比例；`AssignMaxSpToBlackboard` 要求实际我方技力控制器。可用明确存在的有限缩放参数相乘，缺参数拒绝。读取当前属性池时不主动同步编队／光环，不修改生命，也不反写来源参数。简单属性子项创建／结束后的读取可走只读顺序预览，限已核攻击、防御、法抗和敌方移速。预览区分提交与入队，读取排除待结束项；不执行回调、推进时钟或消耗随机数。最大生命变化、状态、复杂生命周期、合并策略与形态／伤害后的快照仍拒绝，保留明确未绑定原因。

Buff 自身带属性修饰器又包含实体属性读取时，仍保守拒绝：出生前预检尚不能完整验证自身出生后的缓存与通知。此边界和属性子项的受限顺序预览分别处理；不能把已接简单子项说成任意动态属性反写或自身快照已完成。

无限触发注册监听在初始黑板有 `trig_cnt` 时接原有限预算，接受范围内整数值，不猜小数转换。显式有限次数优先，计时器、寿命、父子关系和其他通知沿原逻辑；之后改黑板不自动重置预算。该数据规则见 [PRTS：BUFF](https://prts.wiki/w/BUFF)，准确初始化／通知相位仍为候选。

资料边界重新区分：常规最大生命变化保持生命比例见 [PRTS：生命值](https://prts.wiki/w/生命值)，五种叠加策略的基本规则见 [PRTS：BUFF](https://prts.wiki/w/BUFF)，就近取整为半数取偶见 [PRTS：就近取整](https://prts.wiki/w/就近取整)。这些属于已有资料而通用实现待补，不再统称规则未知。一般来源隔离、重加时触发预算／快照处理、复合算术的具体节点顺序和负数求余尚未定论；特殊生命池不能仅凭常规比例规则宣称完成。

引擎不会把所有干员、敌人、伤害和技能都放进同一种简单顺序。普通实体按更新优先级与共享创建顺序推进；部分延迟效果、弹体、Buff 与特定攻击有自己的处理阶段。改变阶段顺序可能影响同帧可见的目标位置、伤害和技能状态，因此目录整理与查看工具不会改动这些规则。

本地 `operator_attack_timing.json` 可按角色及其 `skills` 配置 `attack_duration`、`attack_hit_time`。默认沿用现有按有效攻击间隔缩放的候选流程；技能指定 `timing_scale="FIXED"` 时，前摇取非负的 `attack_hit_time` 与 `min_hit_time` 的较大值，不随攻击间隔缩放。正前摇仍交给主引擎的固定帧待命中包，不另建伤害时间轴。缺少普通和技能动作数据时，部分动作仍立即结算；独立的投射物落地时间不能用前摇代替。

多段动作可配置与段数相同的 `attack_hit_times`，每段分别等待对应事件，沿用同一动作开始时的缩放；也可用 `additional_attack_interval` 表示第一段之后的固定发射间隔。后续帧存于同一个待命中动作中，打断时一并取消，最后一段才通知一次攻击完成／弹药消耗；远程每段独立创建弹体，不在一个弹体上一次性结算整个连射。未经配置的零间隔多段仍为同次事件的多个伤害包。回放的技能状态保存 `pendingHitFrames`，用于查看待执行段数；实际接续继续重建完整引擎状态。

名单内 31 名角色的 36 个所选技能已有动作配置，复用同一待命中流程；音符、消耗仆役和回费也可以作为无需敌方目标的动作等待事件。星熊三技能采用独立固定周期，按当次目标结算；持续技能可配置 `startup_duration`。来源、方向选择和动画缩放仍为候选，既有形态／治疗／锤击校准流程保留。

普通追踪攻击可在普通／技能时序配置中分别声明 `projectile_key`、`projectile_delay_after_reached` 和 `keep_projectile_after_departure`。数值速度仍从本地弹体数据读取；到达后延迟与飞行分开，不把伤害提前到出手事件。配置不自动覆盖特殊运动、链条、治疗弹体或投掷落点；这些继续由对应运行时处理。`select_target_timing` 和 `recover_sp_if_target_dead` 只描述已接入的出手重选／单次死亡退款路径，不能当作所有失效通知都已原生验证。

普通追踪弹体与已接入的炼金投掷共用干员出手点选择：在实际发射事件查询动态姿态，必要时朝向当次目标；炼金投掷记录固定出手点，再沿现有二维路径飞到落点。目标为自身格也不能跳过出手点到落点的距离。已有图形资料而缺少弹体绑定时报告 `OPERATOR_PROJECTILE_BINDING_MISSING`，缺少资料继续中心回退。公共技能的子发射器不自动继承携带者挂点；治疗、音符、拉拽及无人机需分别接入。骨骼资料解析、实际发射检查和原生逐帧验证是不同覆盖范围。

## 随机判定的定向分析

`Battle(..., random_trace=True)` 使用与默认模式相同的 PCG32 序列，并可通过 `battle.rng.export()` 导出判定记录。每项包含 `kind`、`parameters`、`context`、同语义判定次数 `occurrence`、实际结果、原抽样结果以及本次消耗的原始整数。伤害处理区分暴击与各条闪避规则，命中率判定在原调用位置记录。

需要隔离某个概率分支时，可把记录作为 `random_tape` 传入，仅修改对应项的 `result`。来源、目标、候选目标顺序、逻辑帧、机制标识及参数必须保持一致；有缺项、余项或不一致即拒绝，`Battle.run()` 自动核对完整消费。自行逐帧运行时，结束后调用 `battle.rng.assert_consumed()` 核对。复演会照常推进模拟随机轴，记录被指定的结果与自然抽样结果，并标记 `outcome_replay=true`；这种运行只能说明指定分支下的行为，不能证明自然触发率或通关概率。

新增机制应通过具名抽样接口提供稳定实体编号和语义信息：`random_uniform(lower, upper, mechanism=..., source=..., details=...)` 返回左闭右开的连续数值；`choose_random_target` 接受机制与来源说明。相等的连续上下界不消耗随机数，单个候选目标沿用原流程消耗一次抽样。未经这些判定入口的直接随机请求不具有语义记录。

相同种子只保证本引擎在相同抽样顺序下重现自身结果。指定结果复演与随机算法、概率规律的验证应分别处理。

也可以直接向 `Battle` 传入 `squad`（`OperatorPlan` 配装列表，时间和坐标不参与携带效果）。显式编队要求所有操作引用已携带干员，部署配装必须与编队一致。不传编队时，从每名干员的首条部署推断携带配置；不同部署配装仍保留，但出现歧义时输出诊断。队伍天赋范围与候选边界见 [编队效果](SQUAD.md)。

如需逐帧使用，创建 `Battle` 后自行调用 `step()` 并检查结束条件。不要在 `run()` 完成后再对同一实例调用 `run()` 期待新的一局；每次计算建立新实例。

`data.py` 的数据目录是进程级配置，切换数据目录需重新加载输入。批量入口的工作进程接收独立配置；不建议在同一进程的多个线程中交替设置不同数据目录。

维什戴尔普通／S1 在现有追踪弹体流程中分别处理到达与停止。S1 子载体分别发射并缓存出手点，停止等待与伤害／状态分开；途中失去有效目标后保留缓存终点，已到达地面载体保留落点。超时先处理资源中的结束到达通知，再处理运动强制到达与停止伤害，不重新等待到达延迟。残影关联来源天赋、刷新／消耗／离场清理，随机模板触发顺序和每载体限制在技能运行时处理，不依赖“命中过”的集合。

魂灵之影复用同一单位、动作、技力、伤害与弹体流程，独立记录生命及自动技能，不触发普通攻击。第二天赋出生与 S3 召唤分支检查当前范围／空部署格／数量上限；生成单位读取本地属性并关联持有者，不占部署人数，持有者离场统一清理。迷彩按登场附加及来源退出处理，已有临时迷彩不会因覆盖而变为永久。攻击弹体缓存其终点，停顿和宿主残影在命中时处理，随机返技力在动作结束时处理并可严格复演。回放保存 `summoner`、`camouflaged` 和 `soulWards`。出生／动作相位、筛选细节、三维投影、超时／失效、复杂状态叠加和原生随机调用仍为候选，S3 本体攻击不在该召唤分支内。

荒芜拉普兰德一技能的独立浮游与本体攻击分开更新：初始态从本体出手事件安排延迟，切换态按各单元目标和周期推进。两状态复用技能控制入口与属性生命周期，不另建战斗引擎；回放状态记录浮游数量和各自目标，查询快照不推进随机流。各独立能力保存目标与已完成成长，首次实际命中的能力确定交接主单元；其停止时将成长转回普通态。重锁同一目标继续成长，换目标重置，阶段提高上限后的命中先推进成长再结算。切换中断普通态子弹体，已有本体弹体沿用原路径。状态映射、动作混合、缓存组合与返回相位仍为候选；原生随机流对齐与完整三维投影暂缓，具体范围见技能支持表。

可选本地时序中的 `projectile_lifecycle` 只应用到逐键核对的普通、治疗和技能弹体，当前有 30 个键；特殊链条、盾牌、音符、浮游仍由各自流程处理。有限寿命从出生阶段计算，在运动前检查；来源失效停止与到期共用已核对的停止路径，目标失效保存最后有效终点，固定终点不随目标移动。未配置的弹体保留原有失效行为。具体标志、原生句柄销毁与来源离场清理不是同一概念；当前默认控制代码、热更实际选择及跨实体通知仍需核对。

逻各斯天赋的随机出生等待在创建时抽取，出手挂点先缓存；等待期间不运动、不伤害、不显示，出生后才计飞行寿命。该决定参与随机记录与严格复演；原生 deterministic／trivial 随机源选择和固定延迟队列相位仍为候选。回放查询不额外抽签。

投币与余弹倾泻共用结束连射排程，等待各自动画事件，分别按 0.07／0.05 秒发射；期间不发起普通攻击或新技能。每发缓存伤害并走真实弹体，打断取消尚未发射的段，已发射弹体按各自配置继续。投币保持开始时标记的地面敌人，余弹按当前候选重选；投币正常结束与打断均执行清技力。新约能天使炸弹另保存独立出生／停止阶段、实际半径及固定落点，来源退场时按来源管理规则清理。技能状态保存 `endVolley`，便于回放和续编；事件量化、选择器通知、缓存组合及复杂打断仍保留候选边界。

## 结果字段

| 字段 | 含义 |
| --- | --- |
| `win`、`reason` | 是否全清，以及 `all_clear` / `life_points_depleted` / `timeout` / `operation_failed` |
| `time` | 结束时的模拟秒数 |
| `life_points`、`max_life_points` | 剩余与初始生命 |
| `enemies_spawned`、`enemies_killed`、`enemies_leaked` | 出场、击杀、漏怪计数 |
| `operators_deployed` | 结束时仍在场的存活干员数，并非部署动作总数 |
| `operator_metrics` | 各次部署的属性、伤害与存活统计 |
| `operation_results` | 全部计划操作的状态、时间、失败原因和上下文 |
| `seed`、`random_draws` | 种子与实际随机抽取次数 |
| `behavior_warnings`、`unsupported_behavior_nodes` | 行为模板未覆盖情况 |
| `behavior_components` | 组件挂载状态、实际接入事件和未接入原因；目录条目数不等于完整能力覆盖数 |
| `mechanic_warnings`、`unsupported_mechanics` | 已能识别的机制缺口 |
| `assumptions` | 本局采用的近似规则说明 |
| `spawn_timing`、`enemy_attack_timing` | 使用的时序模式 |

这是胜负与诊断摘要，不是完整的战斗调用轨迹。回放工具另外保存每帧状态与由状态差生成的事件。

可选本地 `operator_graphics.json` 提供干员默认外观的前后面动画挂点采样及各弹体的单点／随机／循环出手组。主引擎沿用现有动作速度取样，左右镜像只作用于列偏移，已发射弹体保留出手位置。读取或显示挂点不会消耗随机数；实际发射的随机组选择进入随机记录。缺少资料时继续使用中心出手，缺少已配置挂点则报告诊断。回放单位可显示当前挂点，弹体保留出手点与挂点标识；续编输入签名包含这份本地资料。真实转身、动画混合、投影和调用顺序尚未闭合。

角色形态适配器还保存明确的切换与总攻击事件。动画配置来自本地 `operator_forms.json`；缺少配置会诊断，静态参数不等于固定帧执行顺序已验证。当前结城理三技能优先覆盖满潜能配置，返回本体时单独保留 `ALL_OUT` 总攻击阶段：保持无敌及普攻／技能限制，允许回复技力，尾段结束保留已回复技力。切换不统一释放全部阻挡，进入零阻挡形态按配置阶段释放；返回时保留阻挡关系。一次实战轮询支持阶段划分，具体进入时间和致命伤后的附加延迟来自可选配置；动画事件、伤害快照和特殊对象交接仍属候选。
