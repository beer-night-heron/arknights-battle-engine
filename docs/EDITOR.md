# 图形化编写操作

沙盘关卡可选择各级附加条件。条件保存在完整方案中并传入运行器；禁部署格同时用于地图和方案校验。当前只执行已接入的规则，特殊环境、机关和分支仍需查看模拟诊断。

支持战备补给的关卡会显示补给选项，校验选择上限、重复项和基础／升级项互斥。完整方案保存 `options.battle_buffs`，运行和回放沿用该选择；续编不能修改历史补给。关卡提供的净化机关卡出现在操作列表，练度按关卡预设读取，不作为普通携带干员。多实例禁锢装置分别操作的完整页面入口仍未接入。

在项目根目录启动本地编辑器：

```powershell
python tools/editor.py
```

然后打开 `http://127.0.0.1:8873/`，先选“写操作”或“看回放”。旧的 `planner.html` 地址会进入同一工作台的写操作模式。保持运行窗口打开；退出时按 Ctrl+C。工具只使用 Python 标准库，仅监听本机，不会把游戏数据或计划发到外部服务。其他数据目录或端口可用 `--data-dir "数据目录"`、`--port 8874`；输出根目录默认 `local/`，可用 `--output-dir "本地目录"` 更换。

工作台 `viewer/index.html` 仍可直接双击，选择看回放离线使用；写操作和回放续编需要服务读取本地数据并运行引擎。两种模式切换时保留已载入的回放和普通编排内容。

## 先准备关卡和队伍

1. 在“关卡与队伍”搜索并选择地图。列表只显示本地已经导入对应关卡文件的项目；同名关卡用 ID 区分。
2. 搜索干员。首次选择默认最高精英化、满级、200% 信赖、满潜能，携带第一技能并选最高已解锁技能等级／专精。下表中的干员优先携带加强编队效果的模组，其余选第一个已解锁模组，均取最高已解锁等级；没有技能或模组时不携带。可在右侧自行调整，重新打开已有队员时保留原配装。
3. 点击“加入队伍”。点击已有队伍卡片可修改练度，再点“保存练度”。同一名干员在当前方案使用统一配装，之后的每次部署沿用它。
4. 点击“开始编排操作”。手动技能默认等待开技能操作；需要自动释放时在配装中明确开启。

| 干员 | 默认模组 | 携带收益 |
| --- | --- | --- |
| 艾雅法拉 | CCR-X | 携带时增加术师攻击力 |
| 黑 | ARC-X | 与另一名狙击同队时增加狙击攻击力 |
| 可露希尔 | TAC-X | 加强罗德岛攻击力加成，保留费用透支 |
| 归溟幽灵鲨 | PUM-Y | 加强深海猎人生命与自然技力回复 |
| 斯卡蒂 | DRE-Y | 加强深海猎人攻击与生命 |
| 安哲拉 | DEA-X | 加强深海猎人攻速 |
| 黍 | GUA-Y | 加强四岁加攻及场上职业条件收益 |
| 年 | PRO-Y | 加强重装生命上限 |

上述默认按携带支援用途选择，不代表所有部署打法都适合该模组。首选模组在本地数据中缺失或未解锁时回退可用模组；已有方案及手动选择不受影响。

选择项按表内解锁条件筛选，保存时复用引擎的完整配装校验。潜能显示为一潜至该角色上限，导出仍使用引擎的增量编号。右侧属性预览为基础配装属性，战斗中的技能、天赋与其他修正以实际模拟为准。携带列表不会限制账号是否拥有这些角色，也没有好友助战、重复同角色或运行中更换携带技能的功能。

携带但不部署的干员也会传入主战斗引擎，用于已支持的编队天赋。来源在场才生效的效果仍需实际部署；对应技能、天赋和模组的未完成部分见 [编队效果](SQUAD.md)。

## 再编排时间操作

- 选择携带干员、操作类型和时间。秒数与 30 Hz 逻辑帧联动；非整数帧时刻仍按引擎的最早执行时间处理，旁边的帧数是近似显示。
- 部署时，在地图上点高亮的可部署格，选择朝向，再点“加入操作”。行 0 在最下方，列 0 在最左侧。
- 撤退、开技能、主动结束和模式切换不需要坐标。技能操作只开放当前携带技能支持的类型。
- 点击右侧操作可修改；同一时刻用上下箭头调整先后顺序，其他时刻按时间排序。删除按钮只移除该条操作。
- 可选择条件不满足时等待、跳过或停止。等待会阻塞后续计划；费用、冷却、技力和在场状态由运行时检查。

地图只显示截至滑块时刻的计划部署；不会预测死亡、费用不足、再部署失败或等待造成的实际延期。同格冲突会标在格子的提示中，“检查计划”也不等于整局操作一定成功。已有技能特殊效果和候选时序的限制仍见 [机制支持与缺口](MECHANICS.md)。

携带酒神二技能或凯尔希·思衡托三技能时，操作对象会增加对应的诱导装置或战术锚点，名称后显示携带者。无需再加一名队员，练度自动继承携带者；更换技能后只开放关联的操作对象。它们的部署仍检查携带者在场、技能、冷却、费用和地块。锚点需要放在携带者当前范围外的远程位；地图只提示地形，最终范围由运行时判断。自动产生的仆役与冻结蓝门会出现在回放详情中。

## 保存、导入与运行

编辑时会自动保存草稿，状态栏显示“草稿已保存”及时间。关卡、队伍、操作、当前编辑步骤、地图时刻，以及尚未确认的练度和操作表单都会保留；空值或未完成的表单也能保存。重新打开页面后，点击“恢复草稿”继续，或选择“开始新方案”。同一页面刷新时优先读取该页面的草稿；新页面提供最近的一份草稿。

草稿快照保存在 `local/editor/drafts/`，每次写入新文件，服务重启后仍可读取。不同页面分别写入，不覆盖彼此或历史快照。浏览器只记住本页的草稿编号，不存放方案内容。若状态栏显示草稿未写入，请保留页面并检查本地服务；恢复需要对应的本地角色和关卡数据仍可读取。

草稿与正式方案分开。恢复本身不会把表单加入方案。操作仍需点击“加入操作／保存修改”，保存、导出和运行只使用已加入的操作；练度沿用原流程，可点击“加入队伍／保存练度”，也会在保存方案或开始编排前校验并加入队伍。正式保存之后，状态栏仍会单独提醒尚未确认的操作表单。

“保存方案”保存关卡、队伍练度、全部已加入的操作和模拟选项，并提供浏览器下载。即使浏览器没有弹出下载，也能从页面提示的本地路径读取：

```text
local/plans/editor/<保存编号>/project.json  完整编辑方案
local/plans/editor/<保存编号>/plan.json     引擎操作 JSON
local/plans/editor/<保存编号>/squad.json    完整携带配装
```

每次保存使用新目录，不覆盖先前文件。“导出操作 JSON”生成相同的三份本地文件，并下载 `plan.json`。操作数组不包含关卡、模拟选项或未部署队员；独立运行需另指定这些参数，并用 `--squad` 指向配套的 `squad.json` 才能保留完整携带天赋。导入完整 `project.json` 继续编辑会保留编队。

“导入”支持完整 `project.json` 或原有的操作数组 JSON。旧操作数组不包含地图，需先选对应关卡；同一干员多次部署使用不同配装时会拒绝导入，避免丢失原配置。整个方案导入时会替换当前编辑内容，有未保存修改时页面会提示。尚未点“加入操作／保存修改”的操作表单不在保存内容中；未保存的练度修改会在保存方案或开始编排前校验并加入队伍。

“运行模拟”调用原有主战斗引擎，不另写一套页面结算。完成后点击“打开本次回放”，在同一工作台切到回放模式；之后仍可点击“退出当前文件”选择其他本地回放。

```text
local/最新模拟/                 最近一次成功生成的回放与结果
local/模拟历史/                 上一版结果
local/editor/runs/<运行编号>/   本次方案、操作、携带配装、运行日志及固定回放副本
```

同一编辑器服务一次运行一局。运行后继续改方案时，已生成的回放仍对应运行时的快照，页面会说明内容已有修改。已完成任务的快捷回放链接在服务重启后仍可读取，只要对应运行目录保留。当前运行器最多推进 600 秒；超出此时间的操作会给出提示。

## 在回放状态下续编

1. 在看回放模式暂停到想调整的帧，点击“从当前帧续编”。地图保留这一帧的真实单位、生命、费用和技力；事件流和播放控件收起，右侧换成操作表单与序列。
2. 切入帧及之前的计划操作锁定，包括仍在等待的操作；等待仍会阻塞后续计划。新操作最早从下一逻辑帧执行。之后的操作可编辑、删除和调整同刻顺序。关卡、携带队伍、练度和模拟选项保持原值。
3. 点击地图格子选择部署位置，点击在场单位或待部署卡片选择干员。选择朝向、时刻和操作后，仍需点击“加入操作”。地图始终显示切入状态，新增位置标记仅提示当前表单；未来死亡、费用和操作结果要重算后查看。
4. 点击“重算后续”，完成后点“打开本次回放”，同页显示新结果并定位到切入附近。新回放还能再次续编，也可以回到更早的帧建立另一条后续方案。“返回原回放”退出当前续编，原回放文件保留。

新编辑器回放携带完整原方案与续编记录。手动读取回放也能续编；缺少完整方案时补选对应的 `project.json`。不同引擎版本的旧回放仍可查看，但须先用当前版本运行原方案再续编。续编表单当前不自动写入普通编辑草稿，请用“保存方案”另存完整操作计划；该计划用于从开局运行，精确续编链保存在生成的新回放和运行目录中。

引擎会从原输入重建到切入点，保留实体、待命中动作、弹体、冷却、随机数状态以及等待中的操作，再替换未来计划。它核对原回放在切入点及之前的全部已采样状态和事件；不一致时拒绝生成接续结果，保留原文件和最新模拟。显示字段核对不等于保存了原生游戏完整状态，也不消除引擎自身的候选机制。续编输入留在 `local/editor/branches/`，每次运行仍用新的 `local/editor/runs/` 目录。
